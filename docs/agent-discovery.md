# Agent instruction discovery

The repository uses [AGENTS.md](../AGENTS.md) and ordinary Markdown [workflows](../.agents/workflows/README.md). No harness-specific configuration is required. Follow [role-based discovery](development.md#delegation-and-independent-review); the harness may load the entry point automatically, but the agent must select/read the applicable workflow and supporting policy, not every file. Do not configure broad automatic imports of these documents.

## Documented harness behavior

Official documentation reviewed 2026-11-25. Empirical verification of all four harnesses remains outstanding; none was available in the implementation environment.

| Harness | Documented discovery and delegation | Verification in an installed environment |
| --- | --- | --- |
| Codex | [Project instructions](https://developers.openai.com/codex/guides/agents-md) are assembled from global and repository instructions through the working directory at startup. Overrides/fallbacks and the instruction byte limit can affect loading. [Subagents](https://developers.openai.com/codex/subagents) have delegated tasks and agent-specific instructions; permissions and skills may be inherited, but do not assume the parent’s reads or every instruction reached the child. | Start at the repository root; inspect active instruction sources or session logs and use the probe below. Check overrides, working directory, byte limit and subagent enablement. Inspect the child thread separately. |
| Claude Code | [Project instructions](https://code.claude.com/docs/en/memory) support AGENTS.md from v2.1.277; use a current version (at least v2.1.281 avoids documented early support gaps). Default discovery is displaced by project/ancestor CLAUDE.md, .claude/CLAUDE.md or CLAUDE.local.md; settings, exclusions and plugin disablement can change it. [Subagents](https://code.claude.com/docs/en/sub-agents) normally receive project instructions, but Explore, Plan, web-fetch and omitClaudeMd agents omit them; ordinary non-fork agents do not inherit prior conversation or reads. | Check version, Project instructions in /config and the root path in /memory (current versions). Run the probe in a normal independent child, and in any other child type actually used. Explicitly read the file if absent. |
| OpenCode | [Instructions](https://opencode.ai/docs/instructions) in current V2 load global and workspace ancestor AGENTS.md files, then configured instructions; deeper files are discovered as areas are read. Workspace location and OPENCODE_DISABLE_PROJECT_CONFIG can suppress project discovery. [Agents](https://opencode.ai/docs/agents/) run child sessions with fresh context and their own permissions; project instructions are added to agent prompts, not a guarantee of prior reads. | Start a session in the repository workspace; inspect instruction-source information if exposed and run the probe in both primary and child sessions. Check actual workspace, configuration and child permissions. Start a fresh session for stale nested instructions. |
| OpenChamber | [OpenChamber 2](https://openchamber.dev/blog/opencode-v2/) uses OpenCode 2; instruction discovery depends on the actual underlying OpenCode server/workspace. Its [agent control tool](https://docs.openchamber.dev/agent-control-tool/) can create separate sessions/worktrees where supported; local/remote and extension/plugin setups differ. A new session is not evidence of inherited instructions. | Confirm the connected OpenCode version and actual checkout/worktree in OpenChamber; follow OpenCode discovery checks. Probe the actual delegated session or child, not just the UI's primary session. |

Do not add vendor compatibility files, symlinks, generated duplicates or custom loaders. If automatic discovery is missing, direct the agent to read the root AGENTS.md explicitly; resolve inaccessible or conflicting instructions before work. Older versions are not a compatibility target.

## Lightweight verification

Run detailed checks on initial setup, after harness/configuration changes, or when discovery seems wrong. For each harness record version, working directory/ref, primary and child source-discovery evidence, and pass/fail/not-run status in the applicable task/PR or a relevant temporary finding. Do not claim that a documented capability has been empirically verified.

Use a read-only probe in a fresh primary session before explicitly directing it to read AGENTS.md: ask it to identify repository guidance already available, the rule for mutation survival, the review-only permission boundary and how it would select a workflow. Inspect native source evidence when available and distinguish initially loaded text from subsequently read text; an answer alone is not proof of automatic injection. Then ask it to select and read the review workflow and referenced testing/review sections. Verify it can accurately explain the relevant requirements with source references. Repeat in a full-task independent child and a focused child with the appropriate assignment references, checking actual reads/source evidence. No code edits, mock policy files or user configuration changes are required. If evidence is unavailable, mark automatic discovery unverified and use explicit reads.

For routine assignments use the much smaller acknowledgement/read-evidence check in the [delegation policy](development.md#delegation-and-independent-review); no recurring detailed probe or policy transcript is required.

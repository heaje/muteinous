# Installation discovery (M2.2)

D132–D133 and D137–D138: candidate locations and names are untrusted launcher metadata, not support or installation authorization. Manual folder intake is independent of launchers. There is no comprehensive scanning entry point in this slice, and selecting or discovering a candidate never opens game content. Explicitly invoke the lightweight probe when useful; a future user-requested comprehensive scan is separate.

Windows sources: Steam HKCU SteamPath, HKLM InstallPath (both registry views), conventional ProgramFiles roots, modern and legacy libraryfolders.vdf and appmanifest ACF; Epic ProgramData/Epic/EpicGamesLauncher/Data/Manifests .item JSON; GOG HKLM/HKCU Software/GOG.com/Games registry records (both views). No game catalog is used. [Steam data format](https://reverseengineering.wiki/index.php/Format:Steam_client_data_files) supports the ACF and modern VDF structure; [observed launcher layouts](https://github.com/VantaCode420/SmartHdrManager/blob/main/Library.cs) support the Steam registry values, steamapps layout, Epic JSON fields and HKLM GOG path/gameName. Other registry views/hives are best-effort searches, not evidence of real registrations. [Epic documentation](https://dev.epicgames.com/documentation/en-us/unreal-engine/multiple-launcher-unreal-engine-installs) confirms the usual ProgramData root but documents relocated PCB-mode data, which is not discovered here. Actual launcher installations still require Windows validation.

Implementation choices, not new architectural requirements: at most 4,096 discovery entries/records, 1 MiB per metadata file and 16 MiB aggregate file metadata reads (one possible final overflow-detection byte); registry API responses are subject to Windows limits, not that file-byte budget. A probe examines at most 128 entries at depth zero through two, requests at most four unbuffered bytes per ordinary file, and skips symlinks, reparse points and special files, including a linked probe root. OS read-ahead and check/open races are not controlled by these application limits. A STRM signature is only a provisional AST hint; a missing signature is not proof of absence. A probe's issues and truncation describe incomplete evidence. Canonical existing directories are deduplicated by exact resolved spelling rather than assuming case-insensitive equality; unresolved candidates are retained with availability status. Explicit parent traversal, malformed path strings and Windows device/reserved paths are refused. An Epic incomplete-install flag is reported, not proof of a playable installation. Oversized metadata and interrupted or incomplete probes are marked truncated. Cancellation is cooperative between bounded operations; an already blocked OS call cannot be preempted. No game or launcher metadata writes, hashing, decoding, ASR, or dependency additions.

Portable synthetic fixtures exercise metadata parsing, candidate deduplication, manual selection, errors, cancellation and probing. The Windows-only registry boundary test uses read-only test doubles; it is not verification against a physical installation. Required CI and independent review evidence belong in the PR. No acceptance or compatibility claim is made from this checkpoint.

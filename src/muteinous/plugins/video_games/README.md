# Installation discovery (M2.2)

D132–D133 and D137–D138: candidate locations and names are untrusted launcher metadata, not support or installation authorization. Manual folder intake is independent of launchers. There is no comprehensive scanning entry point in this slice, and selecting or discovering a candidate never opens game content. Explicitly invoke the lightweight probe when useful; a future user-requested comprehensive scan is separate.

Windows sources: Steam HKCU SteamPath, HKLM InstallPath (both registry views), conventional ProgramFiles roots, modern and legacy libraryfolders.vdf and appmanifest ACF; Epic ProgramData/Epic/EpicGamesLauncher/Data/Manifests .item JSON; GOG HKLM/HKCU Software/GOG.com/Games registry records (both views). These layouts are documented or observed generically; no game catalog is used. See [Steam data format](https://reverseengineering.wiki/index.php/Format:Steam_client_data_files), [Steam registry/library evidence](https://github.com/MetaHookSv/SteamAppsLocation), [Epic documentation](https://dev.epicgames.com/documentation/en-us/unreal-engine/multiple-launcher-unreal-engine-installs) and [observed Epic/GOG metadata layouts](https://github.com/VantaCode420/SmartHdrManager/blob/main/Library.cs). Actual launcher installations still require Windows validation.

Implementation choices, not new architectural requirements: at most 4,096 discovery entries/records, 1 MiB per metadata file and 16 MiB aggregate metadata reads (one overflow-detection byte); a probe examines at most 128 entries at depth zero through two, reads at most four bytes per ordinary file, and skips child symlinks and reparse points. A STRM signature is only a provisional AST hint; a missing signature is not proof of absence. A probe's issues and truncation describe incomplete evidence. Canonical existing directories are deduplicated by resolved path; unresolved candidates are retained with availability status. Cancellation is cooperative between bounded operations; an already blocked OS call cannot be preempted. No game or launcher metadata writes, hashing, decoding, ASR, or dependency additions.

Portable synthetic fixtures exercise metadata parsing, candidate deduplication, manual selection, errors, cancellation and probing. The Windows-only registry boundary test uses read-only test doubles; it is not verification against a physical installation. Required CI and independent review evidence belong in the PR. No acceptance or compatibility claim is made from this checkpoint.

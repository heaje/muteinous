# Installation discovery (M2.2)

D132–D133 and D137–D138: candidate locations and names are untrusted launcher metadata, not support or installation authorization. Manual folder intake is independent of launchers. There is no comprehensive scanning entry point in this slice, and selecting or discovering a candidate never opens game content. Explicitly invoke the lightweight probe when useful; a future user-requested comprehensive scan is separate.

Windows sources: Steam HKCU SteamPath, HKLM InstallPath (both registry views), conventional ProgramFiles roots, modern and legacy libraryfolders.vdf (config first, steamapps fallback when absent) and appmanifest ACF; Epic ProgramData/Epic/EpicGamesLauncher/Data/Manifests .item JSON; GOG HKLM/HKCU Software/GOG.com/Games registry records (both views). No game catalog is used. [Steam data format](https://reverseengineering.wiki/index.php/Format:Steam_client_data_files) supports the ACF and modern VDF structure; [SKIF Steam library discovery](https://github.com/SpecialKO/SKIF/blob/master/src/stores/Steam/steam_library.cpp) corroborates both VDF locations and layouts; [observed launcher layouts](https://github.com/VantaCode420/SmartHdrManager/blob/main/Library.cs) support the Steam registry values, steamapps layout, Epic JSON fields and HKLM GOG path/gameName. Other registry views/hives are best-effort searches, not evidence of real registrations. [Epic documentation](https://dev.epicgames.com/documentation/en-us/unreal-engine/multiple-launcher-unreal-engine-installs) confirms the usual ProgramData root but documents relocated PCB-mode data, which is not discovered here. Actual launcher installations still require Windows validation.

Implementation choices, not new architectural requirements: at most 4,096 processed discovery entries/records, 1 MiB per metadata file, 64 KiB per registry value and 16 MiB aggregate metadata bytes (one possible final file overflow-detection byte). Directory enumeration may obtain one extra entry to detect truncation. Registry reads use a fixed buffer with [RegQueryValueExW](https://learn.microsoft.com/windows/win32/api/winreg/nf-winreg-regqueryvalueexw), refuse unsupported types and never resize on ERROR_MORE_DATA. A probe examines at most 128 entries at depth zero through two, requests at most four unbuffered bytes per ordinary file, and skips symlinks, reparse points and special files, including a linked probe root. OS read-ahead and check/open races are not controlled by these application limits. A STRM signature is only a provisional AST hint; a missing signature is not proof of absence. A probe's issues and truncation describe incomplete evidence. Canonical existing directories are deduplicated by exact resolved spelling rather than assuming case-insensitive equality; unresolved candidates are retained with availability status. Explicit parent traversal, malformed path strings and Windows device/reserved paths are refused. An Epic incomplete-install flag is reported, not proof of a playable installation. Oversized metadata and incomplete probes are marked truncated; discovery issues also describe invalid or inaccessible observations. Cancellation raises without publishing a partial result. Cancellation is cooperative between bounded operations; an already blocked OS call cannot be preempted. No game or launcher metadata writes, hashing, decoding, ASR, or dependency additions.

Portable synthetic fixtures exercise metadata parsing, candidate deduplication, manual selection, errors, cancellation and probing. Windows-only tests exercise read-only registry-view selection with test doubles and the bounded native reader against a unique temporary synthetic HKCU key (created and deleted only by the test). They are not verification against a physical installation. Required CI and independent review evidence belong in the PR. No acceptance or compatibility claim is made from this checkpoint.

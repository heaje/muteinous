# Implement an issue

1. Follow [full-task discovery](../README.md#task-start-discovery). Read the Issue scope, criteria, dependencies, exclusions and applicable original decisions; verify prerequisite implementation and evidence. Resolve material ambiguity with the maintainer.
2. Start from current verified main in a dedicated branch and isolated worktree/directory. Use a different base only for explicitly authorized stacked work; verify its exact ref and dependencies. Coordinate shared files and avoid concurrent agents' branches.
3. Establish relevant baseline checks. Implement the approved slice without scope expansion, following [engineering principles](../../docs/development.md#engineering-principles), applicable architecture and [testing policy](../../docs/testing.md).
4. Validate with applicable repository commands; map acceptance criteria and D-number decisions to actual implementation and test evidence. Record unverified behavior and limitations.
5. Obtain [independent review](../../docs/development.md#delegation-and-independent-review) of the proposed changes. Confirm findings and correct minimally under the [review policy](../../docs/development.md#actionable-review-findings); revalidate and re-review meaningful fixes. If blocked, provide a checkpoint and request the missing review/check.
6. Commit using Conventional Commits, push the dedicated branch, and create/update a PR with the evidence, scope and risks required by the [work-unit policy](../../docs/development.md#work-unit-and-review-policy). A draft/checkpoint is permitted before the review gate; do not claim completion or merge readiness before satisfying it. Verify pushed head, follow [handoff rules](../README.md), and leave merge to the maintainer unless explicitly authorized.

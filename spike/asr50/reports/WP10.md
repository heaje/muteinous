- **AMD GPU acceleration is unavailable in this runtime on this machine.** CTranslate2 installation is L2 evidence; `ctranslate2.get_cuda_device_count()` returned `0` (L3, CUDA enumeration only). CPU ASR inference succeeded (L5). None of these establishes AMD GPU support.

- `device='auto'` constructed with `model.device == 'cpu'`, compute type `int8_float32`. It selected CPU in the absence of a supported CUDA device; this is observed resolution, not an observed silent fallback after a GPU inference failure.

Practical D48 implication: Automatic selects CPU here, with no Radeon ROCm/HIP acceleration. Explicit CUDA did not silently fall back; it raised during construction, consistent with D49. This does not test GPU-op failure fallback on a supported GPU.

## Target-metric rescore correction

The prior target precision/recall discrepancies came from **aggregation method**, not different audio files, configurations, or token normalization. Earlier scoring flattened target-token sequences across clips and called `score.target_metrics` once on the concatenation. Because its ordered Levenshtein matching can align occurrences across clip boundaries, duplicated targets and false positives can shift TP/FP/FN. Canonical central scoring calls `score.target_metrics(reference, hypothesis)` per clip, then sums TP/FP/FN. Recomputed this way for all configs:

- V1: unchanged — beam5/VAD off and on P/R 96.8%/85.7%; beam1 P/R 100.0%/82.9%.
- V2 unmasked: beam5/VAD off and on P/R 97.0%/82.8%; beam1 P/R 96.9%/81.0%.
- V2 masked and gated: P/R 97.0%/83.6%.
- V3 raw/VAD-on/masked/gated: P/R 90.00%/95.45% (63 TP, 7 FP, 3 FN).

Accordingly, the v1 table values were verified as already correct; v2 and v3 table values and the v3 summary have been corrected. Updated machine-readable target scores are in the corresponding `scoring_summary.json`, `scoring_comparison.json`, and `scoring_v3.json`. WER/S/D/I, target normalization, and other reported metrics did not change.

**Correction summary (<150 words):** The mismatch was caused by flattening target occurrences across clip boundaries before `score.target_metrics`; the central method runs it per clip and sums TP/FP/FN. This changes edit alignment for repeated targets/hallucinations but does not change transcripts, WER, or token normalization. I rescored all v2 masked configurations and all v3 raw/VAD/masked/gated views per clip, updated WP10's tables and v3 summary, and refreshed the corresponding scoring JSON. Corrected results: v2 masked P/R 97.0%/83.6%; v3 P/R 90.00%/95.45% (63 TP, 7 FP, 3 FN). V2 unmasked scores were also corrected. I checked v1 by the same method; its reported P/R values were already unchanged. No other reports were modified.

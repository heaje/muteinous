# WP19 — DirectML worker stability on RX 7900 XT

## Setup and containment

Disposable Python 3.12 environments:

- `C:\scratch\asr50\WP19\venv-dml`: `onnxruntime-directml==1.24.4`
- `C:\scratch\asr50\WP19\venv-wml`: `onnxruntime-windowsml==1.30.1.202610302006`

Both installed with NumPy 2.5.5, psutil 7.2.2 and tokenizers 0.23.3. No model assets were downloaded. The model was the already-approved local `C:\scratch\asr50\models\whisper-small-en-onnx-fp16`; audio came from `C:\scratch\asr50\corpus_v2_frozen`. The full transcript workload reused `spike\asr50\runners\ort-whisper-small-en\run.py`; isolated child workloads and the timed parent/counter harness are `spike\asr50\directml_stability\asr_child.py`, `probe.py`, and `driver.py`. Harness records, logs, and outputs are under `C:\scratch\asr50\WP19`.

Every experiment ran in child process(es), with a timeout and captured stdout/stderr/exit status; the Python harness snapshots read-only System display/AMD driver events before/after. No matching events appeared for these test windows. Where noted, process-specific memory sampling did not resolve the actual Python worker PID, so memory is `unavailable`, not zero. `Get-Counter \GPU Process Memory(*)\Dedicated Usage` itself returns process instances, but sampled instances did not match the harness-launched worker PIDs; no per-worker peak is inferred.

CPU reference is the exact transcript from CPUExecutionProvider on the same FP16 Whisper files. Its default ORT graph optimization failed during model initialization with `Fail` in `graph_utils.cc` (missing `InsertedPrecisionFreeCast_...Constant_output_0` node); disabling graph optimization allowed CPU inference to complete. Each DML concurrent process emitted exactly the same transcript as this reference.

Provider registration is not proof that all operators ran on GPU; no partition profiling was collected. No matching AMD display/TDR event was found in the System log around the relevant child tests; log absence cannot rule out every driver issue.

## Production interpretation

There is now direct evidence for a meaningful distinction: two independent DML sessions invoked concurrently from threads in one process reproducibly crashed with access violation, while two, three, and four separate processes each completed one real inference with identical CPU-reference text in this test. That supports process isolation as a safer design than concurrent same-process DML execution on this configuration; it does **not** prove those process counts are sustainable in production. Dedicated VRAM per process, long-duration stability, OOM behavior, and all-operator GPU placement remain unknown. Prefer subprocess isolation and conservative worker count; do not assume four workers are a safe deployment setting based on a single short pass.

## Summary (<300 words)

On RX 7900 XT, two DirectML Whisper session sets run concurrently on separate threads in one process crashed with access violation (`0xC0000005`, no output); no matching AMD/System display reset event appeared. In contrast, 2, 3, and 4 separate DirectML processes each completed the same real Whisper small.en clip and exactly matched the CPU reference transcript. A Vulkan whisper.cpp inference also completed alongside DirectML with matching text. This supports process isolation over concurrent same-process DML sessions for this tested configuration, but does not certify process scaling or production stability: per-process VRAM could not be sampled reliably, and low-memory thresholds were not tested because controlled free VRAM could not be established safely. One 200-run encoder test showed identical output and near-flat RSS after session initialization; the last-10 / first-10 mean latency ratio was 1.110×, a small single-run variation without significance testing. Twenty encoder session create/run/destroy cycles completed. Full-model repeated loops timed out at 300 seconds. ORT 1.24.4 Python does not expose `add_provider_for_devices`; memory-pattern and parallel encoder-session functional checks passed. WindowsML 1.30.1.202610302006 completed one real inference, with provider bridge/config warnings. No model downloads, system installs, repo dependency edits, or commits occurred. The result does not prove every model operator ran on GPU or establish safe worker counts under sustained load.

## Fallback and bad-device behavior

- With `session.disable_cpu_ep_fallback=1` and DML requested for `decoder_with_past_model_q4.onnx`, session creation fails exactly: `This session contains graph nodes that are assigned to the default CPU EP, but fallback to CPU EP has been explicitly disabled by the user.` DML cannot initialize this graph as an all-DML session.
- Invalid `device_id=99`: ORT logs `887A0002 The object was not found. If calling IDXGIFactory::EnumAdaptes, there is no adapter with the specified ordinal.` and `Falling back to ['CPUExecutionProvider'] and retrying.` It then returns a session whose providers are `['CPUExecutionProvider']`. The Python call succeeds, so callers must inspect actual providers and reject this fallback for explicit GPU selection (D49); it is not a thrown creation failure.
- `onnxruntime-windowsml` 1.30.1 emitted `Init provider bridge failed.` on import, then enumerated DML/CPU; a q4 encoder session could be created with DML/CPU. No WindowsML inference was performed, so it is not evidence of WindowsML GPU computation.
- No SimplifiedLayerNormFusion / InsertedPrecisionFreeCast optimizer error occurred with the approved q4 model and ORT-DML 1.24.4. The earlier fallback-disabled error is CPU node assignment, not an optimizer failure.

### Fixed chunking and prototype guard

For clips longer than 30 s, split into **non-overlapping 30-s windows**, independently decode each, then concatenate nonempty window texts with one space. No audio is silently truncated. Six clips used multiple windows (70 windows total). This simple policy risks cutting a word at a boundary, losing context, or duplicating/mangling text at joins; no overlap or seam reconciliation was applied.

Default vs energy-gated output was evaluated on all 20 silence/non-speech clips. Prototype: compute the maximum RMS over non-overlapping 10-ms frames and skip decoding if it is <= 0.003 (about -50 dBFS). The local generation config provides no `no_speech_token_id`, so no first-step no-speech probability test was available. The gate skipped the five pure-silence clips and no non-speech clips.

| Guard mode | Combined hallucinated words/min | Clips with output | Silence WPM / output fraction | Non-speech WPM / output fraction |
|---|---:|---:|---:|---:|
| Default | 3.13 | 65% | 4.48 / 100% | 2.69 / 53.3% |
| Energy gate | 2.01 | 40% | 0 / 0% | 2.69 / 53.3% |

This is a prototype, not a production speech detector: it only removed the exact-zero silence clips and did not reduce effects/noise hallucinations. Results are identical for CPU and DML. The export has no native word alignment outputs; no timing metrics were run (WP14 owns alignment).

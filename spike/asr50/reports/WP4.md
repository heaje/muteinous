# WP4 — Candidate runtime research (C–E)

**Research date:** 2026-11-26. Scope: upstream documentation/source and PyPI JSON metadata only. No installs or model downloads. Hardware claims are documentary (L1) unless stated otherwise; no local compute/inference was performed. Hardware context: Windows 11, Ryzen 9 9900X, Radeon RX 7900 XT / gfx1100 (from COMMON.md).

## Decision requirements

Muteinous needs initially English ASR (D51), word-level start/end timestamps (D68–D71), CPU fallback and explicit CPU/GPU device choice (D48–D49), and on-demand approved downloads with independently pinned model revision and SHA-256, verification before use, and offline reuse (D144–D145). A runtime's own download/cache behavior does **not** establish D144 compliance; the application must own provenance, digest verification, staging, approval and cache semantics. Selection itself remains open under D47/D166 pending the spike comparison.

## C. faster-whisper / CTranslate2

### Releases and CPython 3.14 Windows artifacts

PyPI JSON, fetched 2026-11-26: `faster-whisper` **1.2.1**; it is pure Python (`py3-none-any.whl`) and its metadata says Python >=3.9. `ctranslate2` **4.9.1**; its current release file list includes both `ctranslate2-4.9.1-cp314-cp314-win_amd64.whl` and `ctranslate2-4.9.1-cp314-cp314t-win_amd64.whl`. Thus regular CPython 3.14 Windows x64 binary is listed; free-threaded is listed too. Faster-whisper itself doesn't have a CP314-specific wheel requirement. These are metadata/file-list findings, not tested installability (L1 metadata only).

### Runtime, device and timestamps

- CPU compute types include `int8`, `int8_float32`, `float32` and hardware-dependent variants; CPU is the supported fallback. CTranslate2 supports reduced precision/quantization generally (INT8/INT16/FP16/BF16); accepted compute types depend on device/backend and can be queried at runtime. Do not assume every listed type works for each device. [CTranslate2 hardware support](https://opennmt.net/CTranslate2/hardware_support.html), [quantization](https://opennmt.net/CTranslate2/quantization.html).
- Faster-whisper exposes `device="cpu"` or `"cuda"` and explicit `compute_type`; its README gives CPU int8 and CUDA float16/int8_float16 examples. `word_timestamps=True` populates per-word start/end times. Alignment mechanism is Whisper decoder cross-attention alignment with dynamic time warping (DTW), not an external forced aligner. [faster-whisper README](https://github.com/SYSTRAN/faster-whisper#word-level-timestamps), [transcribe source](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py).
- Mainline CTranslate2 GPU docs describe NVIDIA CUDA, but current upstream documentation also describes HIP/ROCm, provides ROCm release wheels and a Windows ROCm build guide; it is not “CUDA only.” The Windows build guide explicitly maps RX 7900 XT to `gfx1100` (**L1 documented hardware mapping**), but this does not prove a prebuilt wheel for CPython 3.14 or successful inference on this machine. ROCm's wheel/runtime is distinct from the standard PyPI binary, and build/runtime constraints apply. No L2–L5 claim is made. [CTranslate2 Windows ROCm guide](https://opennmt.net/CTranslate2/building_rocm_windows.html), [hardware support](https://opennmt.net/CTranslate2/hardware_support.html), [release wheels](https://github.com/OpenNMT/CTranslate2/releases).
- Standard CUDA deployment requires NVIDIA CUDA 12 cuBLAS and cuDNN 9; faster-whisper uses PyAV, which bundles FFmpeg libraries, so a system FFmpeg install is not needed. Package dependencies include CTranslate2, Hugging Face Hub, tokenizers, ONNX Runtime, PyAV and tqdm. [README requirements](https://github.com/SYSTRAN/faster-whisper#requirements).
- Building CTranslate2 from source is not a routine fallback: C++ toolchain/CMake, dependencies and backend-specific SDK/toolchains are required. ROCm on Windows additionally means HIP/ROCm toolchain configuration; these are absent from the machine-under-test inventory in COMMON.md. See [installation/build documentation](https://opennmt.net/CTranslate2/installation.html) and ROCm guide above.
- Licenses: faster-whisper MIT; CTranslate2 MIT. The selected Whisper model's license is separate and must be checked per exact artifact/revision.

### Fit

**Functional fit: conditional yes.** English can be explicitly requested; word-level timings and CPU fallback are present; device can be explicitly selected. NVIDIA path is documented; AMD GPU is not a proven Windows option and likely means remaining on CPU unless maintainer-approved tests establish a ROCm path. D144 fit is conditional: download/load defaults are Hub-oriented, so Muteinous must bypass uncontrolled model resolution and provide exact pinned local assets/digests and offline mode. There is a standard PyPI CP314 binary for CT2, but the distinct ROCm artifact's CP314/Windows/gfx1100 suitability must be checked separately.

## D. Parakeet / sherpa-onnx

### Releases, wheels and Windows

Direct PyPI JSON query on 2026-11-26 returned `sherpa-onnx` **2.0.3**, with `sherpa_onnx-2.0.3-cp314-cp314-win_amd64.whl` and `...-win32.whl` in its current release file list (see [PyPI JSON](https://pypi.org/pypi/sherpa-onnx/json)). This supports a CPython 3.14 Windows x64 install path by published artifact metadata, not a tested install (L1 metadata). The main PyPI distribution is not presented as separate “CUDA” or “DirectML” Python wheel flavors in that JSON result. Check exact per-release file list rather than treating ONNX Runtime provider documentation as proof the sherpa wheel bundles a GPU backend.

### Models, execution providers and timings

- Sherpa-onnx documents Windows x64 and CPU usage, broad local/offline inference, and multiple runtime APIs. The execution backend is model/build-dependent. ONNX Runtime providers include CPU, CUDA, TensorRT, DirectML, OpenVINO, CoreML, etc.; availability is determined by the installed ORT build and device, not sherpa's general platform table. [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx), [ORT execution providers](https://onnxruntime.ai/docs/execution-providers/).
- DirectML is an ONNX Runtime Windows provider intended for DirectX 12-capable GPUs. That makes an AMD GPU *potentially addressable in principle* (L1 provider support), but is not evidence that sherpa-onnx's published Windows wheel uses a DirectML-enabled ORT build, that its model ops are supported, or that gfx1100 inference works. No L3/L4 evidence gathered; classify AMD DirectML as **unverified**, not supported hardware claim. [DirectML EP](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html).
- Official sherpa model catalog includes `sherpa-onnx-nemo-parakeet-tdt-0.6b-v2-int8`, English, converted from `nvidia/parakeet-tdt-0.6b-v2`; model archive is separately downloadable. Catalog supplies int8 export; fp16 availability for this sherpa export was not established in the material checked. Do not assume a corresponding FP16 archive. [Parakeet model recipe](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/offline-transducer/nemo/parakeet-tdt-0.6b-v2.html), [NVIDIA model card](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v2).
- The model is English, suitable for D51. Parakeet TDT provides **per-token timestamps and durations**, not a ready-made guaranteed word-start/end sequence; for English, word times would need to be derived by grouping/subword aggregation and validated. Sherpa's forced-alignment facility is a separate workflow/model, not a blanket property of every recognizer. Sherpa Whisper supports token timestamps and has a recipe using cross-attention weights/alignment heads for word-level timestamps; its exact model export/API requirements must be included. [Parakeet example output](https://github.com/k2-fsa/sherpa-onnx/blob/master/python-api-examples/offline-nemo-parakeet-decode-file.py), [Whisper export/word timestamps](https://github.com/k2-fsa/sherpa-onnx/blob/master/scripts/whisper/README.md), [Whisper recipes](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/whisper/).
- Sherpa runtime source license is Apache-2.0. Parakeet model terms are CC-BY-4.0; attribution is required and license notices/credit must be retained in any redistribution/use covered by the license. Runtime and model license must be tracked independently. [sherpa LICENSE](https://github.com/k2-fsa/sherpa-onnx/blob/master/LICENSE), [CC-BY 4.0](https://creativecommons.org/licenses/by/4.0/).
- NeMo is not a strong Windows/AMD fallback: NVIDIA NeMo's dependency stack and GPU-centric workflows target Linux/CUDA; exports can be produced elsewhere, but sherpa-onnx CPU inference of the exported ONNX is the more plausible deployment route. Native NeMo on Windows/AMD is not documented as supported here and requires a separate compatibility study.

### Fit

**Functional fit: conditional, strongest straightforward CPU/Windows deployment candidate but not yet proven to satisfy word-time requirement as-is.** English Parakeet and sherpa Windows CPU runtime are documented, and CP314 Windows wheels are listed. Explicit CPU selection is feasible; GPU selection depends on provider-specific packaging and validation. ORT DirectML is a possible AMD avenue only at provider level, not currently evidenced for sherpa wheel + gfx1100. Parakeet returns token-level timestamps; Muteinous needs verified token-to-word aggregation or a separate alignment route before claiming its precise word start/end requirement is met. Whisper in sherpa has a documented attention-based word timing route but requires the appropriate export/API. D144 is implementable with a separately pinned model tarball/revision and digest, but upstream model download archive must be integrity-pinned by Muteinous (the catalog download alone is not enough).

## E. Moonshine

### Package names / versions / wheels

The names refer to different generations and should not be conflated:

- `moonshine-voice` **0.1.6** is current per PyPI metadata. PyPI JSON lists `moonshine_voice-0.1.6-py3-none-win_amd64.whl`; pure-Python tag does not mean model/runtime assets are absent from the wheel. Package metadata has classifiers only through CPython 3.12, so CP314 compatibility is not explicitly classified despite the `py3` wheel tag. [PyPI JSON](https://pypi.org/pypi/moonshine-voice/json).
- Legacy `useful-moonshine` latest PyPI JSON version is **20241016**; it has `py3-none-any` wheel. It uses Keras/PyTorch (and heavy optional TF/JAX stack), not the current voice package flow. [PyPI JSON](https://pypi.org/pypi/useful-moonshine/json).
- `useful-moonshine-onnx` latest PyPI JSON version is **20251121**; no cp314-specific Windows wheel indicated by its release tags in the query. It is a third-party/adjacent ONNX package lineage, not interchangeable evidence for official `moonshine-voice` behavior. [PyPI JSON](https://pypi.org/pypi/useful-moonshine-onnx/json).
- `moonshine-onnx` exact project name returned 404 from PyPI JSON at research time. The relevant packaging ecosystem appears to be `useful-moonshine-onnx` and sherpa's own Moonshine ONNX exports; do not cite `moonshine-onnx` as an available PyPI project without new evidence.

### Models, licenses, timestamps, backend

- Current Moonshine Voice lists Tiny/Base and streaming models across sizes. Their exact names/model revisions vary with docs release; check the [available models](https://moonshine-voice.readthedocs.io/en/latest/models/available-models) page when pinning. English models and all streaming STT models are MIT; non-English legacy non-streaming models are under the Moonshine Community License with non-commercial restrictions. Thus the English-only Muteinous use case avoids the known non-commercial caveat, but must still pin the exact English model artifact/license. Code package is MIT. [license page](https://moonshine-voice.readthedocs.io/en/stable/license/), [repository license](https://github.com/moonshine-ai/moonshine/blob/main/LICENSE).
- Moonshine Voice API supports `word_timestamps`; docs say it needs an attention decoder asset (and is implied by speaker identification). It exposes per-word timestamps in transcript line structures. [API options](https://moonshine-voice.readthedocs.io/en/latest/api/options), [PyPI readme](https://pypi.org/project/moonshine-voice/).
- Runtime advertises platform-appropriate execution providers; docs include provider selection, while the ONNX model path uses ONNX Runtime. The exact Windows CPU/GPU provider/device support requires provider-specific setup. No evidence found that the current Windows `moonshine-voice` package provides DirectML/GPU acceleration on AMD. Treat it as CPU fallback available and GPU support on this target **unverified**. Not established “ORT CPU only” categorically, but no reliable AMD DirectML path verified.
- New Moonshine Voice wheels are relatively large and include native runtime/assets; model weights can also be downloaded/cached separately. The package README explicitly describes `load()`/download/cache behavior, and installation can carry bundled code/assets; distinguish wheel contents from model-specific on-demand assets. PyPI JSON lists wheel size/sha256 per release; use those only as package integrity evidence, not model artifact digests.
- Upstream English WER tables are published for Tiny/Base comparisons against similarly sized Whisper on OpenASR datasets; reported averages in legacy model README: Tiny Moonshine 12.66 vs Whisper 12.81; Base 10.07 vs 10.32, with per-dataset rows. Current Voice docs publish their own model accuracy tables (including Tiny/Small/Medium Streaming), but figures vary by model generation and evaluation setup. Do not compare these as like-for-like without matching test set/protocol. [Moonshine accuracy](https://moonshine-voice.readthedocs.io/en/latest/models/accuracy), [legacy README table](https://github.com/usefulsensors/moonshine#readme).
- `useful-moonshine` legacy pipeline is Keras with PyTorch/TensorFlow/JAX backend and Python model download. Its setup can use CUDA via JAX extra, but that does not establish Windows/AMD support; model inference package itself has heavier dependencies and no built-in CTranslate2 route (TODO in upstream). [PyPI project](https://pypi.org/project/useful-moonshine/).

### Fit

**Functional fit: conditional, with caveats.** English Tiny/Base/streaming variants, word-level timing support and CPU use exist. Explicit CPU/GPU override and a supported Windows AMD provider remain unclear/unproven; current official package is more complex and larger than a minimal recognizer, and its download/cache behavior is designed for application convenience, not D144's approval + pinned SHA-256 + offline integrity contract. The official code/model licenses are acceptable for English (MIT); avoid unsupported non-English legacy model artifacts. Validate CP314 support despite the pure-Python wheel tag. D144 can be wrapped by Muteinous only if model fetches are controlled and verified.

## Summary (<400 words)

- **Key findings:** Faster-whisper 1.2.1 + CTranslate2 4.9.1 and sherpa-onnx 2.0.3 publish Windows x64 artifacts compatible by filename with CPython 3.14 (**L1 PyPI metadata**). sherpa-onnx 2.0.3 includes Windows CP314 wheel; official catalog has English Parakeet TDT 0.6B v2 int8 export (**L1 docs**). Faster-whisper supports word timestamps via cross-attention DTW. Parakeet TDT exposes token timing; Muteinous would need validated token-to-word aggregation, while sherpa Whisper has a documented attention-based word timing route. Moonshine Voice 0.1.6 has a generic Windows py3 wheel, word timing option, and English models under MIT; generic tag is not CP314 test evidence.
- **Hardware:** CPU fallback is documented for all three (**L1**). Faster-whisper supports explicit CPU/CUDA and has a separate ROCm/HIP path, but no RX 7900 XT Windows inference evidence gathered. ONNX Runtime DirectML could in principle target AMD but sherpa wheel/provider/gfx1100 compatibility is unverified. No GPU computation, provider enumeration or ASR run was done (no L2–L5 claims).
- **Commands run:** PowerShell `Invoke-RestMethod https://pypi.org/pypi/<name>/json` for six projects and filtered current-release filenames for cp314 Windows/py3 Windows wheel tags. No installs, no SDK changes, no model downloads.
- **Time:** approximately 20 wall-clock minutes, research only.
- **Blockers/approval:** Exact Windows AMD GPU backend compatibility and benchmark is open; CP314 Moonshine behavior needs test; word timing quality should be validated on approved synthetic clips. Maintainer approval is required before any weight download or inference not already authorized by the spike rules; no such action was taken. No runtime/model selection recommended as settled.
